1. ARCHITECTURE OVERVIEW
--------------------------------------------------------------------------------
   +--------------------------+         +------------------------------+
   | Your VPS (any OS)        |         | Lovable Cloud (managed)      |
   |  - Nginx + static SPA    | HTTPS   |  - Postgres database         |
   |  - TLS cert (Let's Enc.) | ------> |  - Auth (email + Firebase)   |
   |  - Optional: coturn TURN |         |  - Edge Functions (call-start|
   |                          |         |      widget-bootstrap, etc.) |
   +--------------------------+         +------------------------------+

The browser:
  1. Loads the SPA from YOUR domain (call.yourcompany.com)
  2. Talks REST/JSON straight to the Lovable Cloud edge functions
  3. Audio uses peer-to-peer WebRTC (DTLS-SRTP) via PeerJS public broker
     (or your own broker — see section 8). TURN fallback in section 9.

2. PREREQUISITES
--------------------------------------------------------------------------------
On your laptop:
  - Node 20+  and  Bun 1.1+   (https://bun.sh)
  - git

On the VPS (Ubuntu 22.04+ recommended):
  - A public IPv4 (e.g. your example: 884.55.55.66)
  - Ports 80 + 443 open
  - A domain pointing at the VPS (e.g. call.yourcompany.com -> 884.55.55.66)

3. BUILD THE FRONTEND BUNDLE
--------------------------------------------------------------------------------
On your laptop:

    git clone <your-repo>  zentord
    cd zentord
    bun install
    bun run build           # output -> dist/

The dist/ folder is a fully static SPA — push it to any web server.

(.env values are baked in at build time. You DO NOT need to set them on the
VPS — the bundle already contains the Lovable Cloud project URL and anon key,
which are PUBLIC. The service-role key is never shipped to the browser.)

4. DEPLOY ON A VPS WITH NGINX (Ubuntu/Debian)
--------------------------------------------------------------------------------
  # On the VPS
  sudo apt update && sudo apt install -y nginx
  sudo mkdir -p /var/www/zentord
  sudo chown -R $USER:$USER /var/www/zentord

  # From your laptop, copy the build:
  rsync -avz --delete dist/  user@884.55.55.66:/var/www/zentord/

  # /etc/nginx/sites-available/zentord
  sudo tee /etc/nginx/sites-available/zentord >/dev/null <<'NGINX'
  server {
    listen 80;
    server_name call.yourcompany.com;
    root /var/www/zentord;
    index index.html;

    # SPA fallback — every route returns index.html
    location / {
      try_files $uri $uri/ /index.html;
    }

    # Long-cache hashed assets
    location ~* \.(?:js|css|woff2?|svg|png|jpg|jpeg|webp|ico)$ {
      expires 1y;
      add_header Cache-Control "public, immutable";
    }

    # Hard-no-cache for index.html so deploys are picked up instantly
    location = /index.html {
      add_header Cache-Control "no-cache, no-store, must-revalidate";
    }

    # Security headers
    add_header X-Frame-Options "SAMEORIGIN";
    add_header X-Content-Type-Options "nosniff";
    add_header Referrer-Policy "strict-origin-when-cross-origin";
    add_header Permissions-Policy "microphone=(self), camera=()";
  }
  NGINX

  sudo ln -s /etc/nginx/sites-available/zentord /etc/nginx/sites-enabled/
  sudo nginx -t && sudo systemctl reload nginx

5. DEPLOY WITH DOCKER / DOCKER COMPOSE
--------------------------------------------------------------------------------
Dockerfile (at repo root):

    # build
    FROM oven/bun:1.1 AS build
    WORKDIR /app
    COPY package.json bun.lockb* ./
    RUN bun install --frozen-lockfile
    COPY . .
    RUN bun run build

    # serve
    FROM nginx:1.27-alpine
    COPY --from=build /app/dist /usr/share/nginx/html
    COPY deploy/nginx.conf /etc/nginx/conf.d/default.conf
    EXPOSE 80

deploy/nginx.conf — same as section 4 (server block).

docker-compose.yml:

    services:
      web:
        build: .
        restart: unless-stopped
        ports: ["80:80"]
        # Mount Let's Encrypt certs if running HTTPS in-container

Run:    docker compose up -d --build

6. HTTPS WITH LET'S ENCRYPT
--------------------------------------------------------------------------------
  sudo apt install -y certbot python3-certbot-nginx
  sudo certbot --nginx -d call.yourcompany.com
  sudo systemctl enable --now certbot.timer    # auto-renew

Browsers REQUIRE HTTPS for getUserMedia (microphone). Do not skip this.

    Value: 884.55.55.66

Wait 2-10 minutes, then run certbot (section 6).

8. SELF-HOSTED PEERJS SIGNALLING (optional)
--------------------------------------------------------------------------------
The default uses the public broker `0.peerjs.com` which is fine for moderate
traffic. For high traffic / lower latency, run your own:

  # On a small VPS:
  npm i -g peer
  peerjs --port 9000 --key zentord --path /pjs &

  # nginx proxy (so it's wss://):
  location /pjs/ {
    proxy_pass http://127.0.0.1:9000;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
  }

Then in src/lib/peer.ts change `host` / `path` / `key` / `secure:true`.

9. TURN SERVER (COTURN) — for users behind strict NAT / corporate firewalls
--------------------------------------------------------------------------------
WebRTC works for ~85% of users with STUN only. The remaining ~15% need TURN.

  sudo apt install -y coturn
  sudo nano /etc/turnserver.conf   # set:
      listening-port=3478
      tls-listening-port=5349
      external-ip=884.55.55.66
      realm=call.yourcompany.com
      lt-cred-mech
      user=zentord:CHANGEME-LONG-RANDOM
      cert=/etc/letsencrypt/live/call.yourcompany.com/fullchain.pem
      pkey=/etc/letsencrypt/live/call.yourcompany.com/privkey.pem
      no-cli
  sudo systemctl enable --now coturn

Open UDP/TCP 3478 + 5349 + UDP 49152-65535 in your firewall.

Then add to src/lib/peer.ts iceServers:
    { urls: 'turn:call.yourcompany.com:3478',  username:'zentord', credential:'CHANGEME-LONG-RANDOM' },
    { urls: 'turns:call.yourcompany.com:5349', username:'zentord', credential:'CHANGEME-LONG-RANDOM' },

10. FIREBASE GOOGLE SIGN-IN SETUP
--------------------------------------------------------------------------------
A. Create a Firebase project at  https://console.firebase.google.com
B. Authentication -> Sign-in method -> enable Google
C. Authentication -> Settings -> Authorized domains -> ADD:
       call.yourcompany.com
       <APP-HOST>            (your existing Lovable preview/published URL)
       localhost             (for local dev)
D. Project settings -> General -> Your apps -> Web app  ->  copy the config:
       projectId, apiKey, authDomain, appId
E. In Zentord:  Admin -> Firebase tab  ->  paste those 4 values  ->  toggle ENABLE
   ->  Save.

That's it — Google login button works immediately. No redeploy needed.
You can change keys / disable Google login anytime from the same screen.

--------------------------------------------------------------------------------
11. DOMAIN WHITELIST ENFORCEMENT
--------------------------------------------------------------------------------
Each company manages its own list at:
    Company Dashboard -> Security -> Domain whitelist

Server enforces it inside the `call-start` edge function:
  - Empty list  = open (anyone can embed)
  - Non-empty   = only listed domains (and their subdomains) work

Your client adds  yourcompany.com  to their whitelist, and ONLY embeds
served from yourcompany.com (or any subdomain) can initiate calls.
The customer's browser IP is NOT checked — only the website Origin.

12. ADMIN PASSWORD RECOVERY  (if you forget the admin login)
--------------------------------------------------------------------------------
You have THREE options. Pick the simplest that works.

  OPTION A — Self-serve (preferred, if you remember the email)
  ----------------------------------------------------------------
  1. Go to /auth and click "Forgot password?"
  2. Enter the admin email — a reset link is emailed (uses your SMTP settings).
  3. Open the link, set a new password.

  OPTION B — Reset via Lovable Cloud dashboard
  ----------------------------------------------------------------
  1. Open Lovable -> Cloud -> Users.
  2. Find admin@gmail.com (or your seeded admin email).
  3. Click ... -> "Send password recovery" or "Set password".

  OPTION C — Direct SQL reset (emergency)
  ----------------------------------------------------------------
  When you've lost everything but still have DB access:

  1. Lovable -> Cloud -> Database -> SQL editor.
  2. PROMOTE any account you can sign in to:

         INSERT INTO public.user_roles (user_id, role)
         SELECT id, 'admin'
         FROM auth.users
         WHERE email = 'YOUR-NEW-EMAIL@example.com'
         ON CONFLICT DO NOTHING;

  3. To force-set a password on an existing auth.users row, use the Cloud
     dashboard's "Set password" UI (Cloud encrypts passwords with bcrypt and
     it's safer than writing crypt() yourself in SQL).

  4. To rename the admin email, run:

         UPDATE auth.users
         SET email = 'NEW@example.com',
             email_confirmed_at = COALESCE(email_confirmed_at, now())
         WHERE email = 'admin@gmail.com';

  5. The seed-admin trigger (handle_new_user) auto-promotes any user whose
     email is admin@gmail.com — so you can always create a new account with
     that exact email and it will become admin on first sign-up.

13. HARDENING / SECURITY CHECKLIST
--------------------------------------------------------------------------------
  [x] HTTPS-only (HSTS preload optional)
  [x] Microphone restricted via Permissions-Policy
  [x] X-Frame-Options: SAMEORIGIN  (prevents clickjacking)
  [x] Service-role Supabase key NEVER in frontend bundle
  [x] All write tables have RLS enabled (verified by linter)
  [x] Firebase ID tokens verified server-side against Google JWKS
  [x] WebRTC media is end-to-end encrypted (DTLS-SRTP, mandatory)
  [x] Per-company domain whitelist server-side enforced
  [x] Per-company plan + quota gating (atomic, race-safe via consume_call_quota)
  [x] Customer call session tokens are random 24-byte hex, expire in 2h
  [x] Razorpay webhooks signed (HMAC SHA-256)
  [x] Password HIBP check enabled (rejects breached passwords on signup)

14. UPDATING TO A NEW BUILD
--------------------------------------------------------------------------------
  bun run build
  rsync -avz --delete dist/  user@884.55.55.66:/var/www/zentord/
  # nginx config has Cache-Control: no-cache on index.html, so users
  # pick up the new build on their next page load.

Edge functions deploy automatically when you push to Lovable.

--------------------------------------------------------------------------------
15. BACKUPS
--------------------------------------------------------------------------------
Lovable Cloud takes daily Postgres backups. To export manually:

  Lovable -> Cloud -> Database -> Backups -> Download

Important user-tables to keep snapshots of:
  companies, employees, calls, payments, subscriptions, plans,
  smtp_settings, razorpay_settings, firebase_settings,
  company_domain_whitelist, firebase_user_map, user_roles, profiles
